# X9 Ultra 实机结果、OTA 与 NFC

[English](COMPATIBILITY.md) | 简体中文 | [项目主页](../README.zh-CN.md)

**本项目仅测试过 OPPO Find X9 Ultra（X9U）真机，具体是一台 512 GB 的 PMA110。** 机主反馈：转为国际版／欧版后，日常使用其余功能正常，已知例外是系统内置 OTA 升级和 NFC 加卡。这是该台手机的使用反馈，不代表对每个功能、每个地区版本都进行了完整测试。

## 实际测试了什么

| 项目 | 已记录范围 |
| --- | --- |
| 实体手机 | Find X9 Ultra / X9U，国行型号 `PMA110`，512 GB，物理项目号 `25021` |
| 首次转版 | 使用已审查的社区 CN2EU 包，从 `PMA110_16.0.9.403(CN01)` 转为 `CPH2841_16.0.9.403(EX01)` |
| 本文“国际版”的含义 | 已记录的 EU/EEA 欧版固件，身份为 `CPH2841` / `CPH2841EEA`；未测试其他国际地区版本 |
| 后续升级 | 另行完成过 EU403 → `CPH2841_16.0.10.500(EX01)` 的手工升级，详情归 OTA updater 项目记录 |
| 新转换工具 CLI | 完成离线包检查和模拟设备测试，尚无新 CLI 从头到尾的实机运行记录 |
| 其他手机或配置 | 没有其他 OPPO 型号、容量、项目号、内核或源版本的实机验证 |

机主最新的 OTA/NFC 反馈描述转版后手机的使用情况，并未针对每个固件版本、App 版本和卡片类型分别复现。实机观察与自动化工具测试范围分别记录在[验证文档](VALIDATION.zh-CN.md)中。

## 转版后的使用反馈

| 范围 | 参考 X9U 的结果 | 可以得出的结论 |
| --- | --- | --- |
| 开机、初始化和正常使用 | 欧版 Android 能启动并完成初始化；机主反馈除下列例外外，日常使用正常 | 已观察到可正常使用的转版结果；不是全部硬件和 App 的完整认证 |
| OTA 通知与下载 | 能收到新的升级推送并下载 | 收到 OTA 不等于系统更新器能够安装它 |
| 系统内置 OTA 升级 | 升级失败，曾在下载完成后提示 `Download failed, please try again` | 该转版配置需要另外处理升级，见 updater 仓库 |
| 国内 NFC App | 机主反馈 App 本身能够正常运行 | App 运行与卡片添加的实际结果需要分别记录 |
| NFC 添加卡片 | 添加卡片请求被 OPPO 拒绝 | 这是该手机已知的开卡／加卡限制，本项目没有已验证的修复方法 |

## OTA：查看独立的 updater 项目

仓库：[oppo china to EU OTA updater](https://github.com/zhangckid/oppo-china-to-EU-OTA-updater)。另见[中文 README](https://github.com/zhangckid/oppo-china-to-EU-OTA-updater/blob/main/README.zh-CN.md)、[设备配置说明](https://github.com/zhangckid/oppo-china-to-EU-OTA-updater/blob/main/docs/PROFILE.zh-CN.md)和[验证记录](https://github.com/zhangckid/oppo-china-to-EU-OTA-updater/blob/main/docs/VALIDATION.zh-CN.md)。

本转换工具负责首次 CN403 → EU403，并包含清除数据；updater 记录已经转版设备的后续完整 OTA 升级流程。该项目有手工 403 → 500 升级成功的实机证据，但当前自动化策略从经验证的 EU500 基线开始，并要求审查过的本地设备配置。公开的示例配置不能用于实际执行。

因此，收到新 OTA 后不要重新运行本转换工具，也不能认为刚转到 EU403 就能直接运行 updater 当前的自动化流程。应先阅读其基线、升级包和设备配置要求。该流程不会让原厂系统更新器重新接受转版手机；updater 自身的自动化实机验证限制仍然适用。两个项目都不通过重新锁定 Bootloader 来处理 OTA 问题。

## NFC：App 正常运行，添加卡片时被拒绝

目前的反馈顺序是：

1. 国内 NFC App 在转版手机上可以正常运行。
2. 用户尝试添加卡片。
3. OPPO 拒绝加卡。

这份反馈**不能直接说明 NFC 硬件损坏，也不等于所有 NFC 功能都不可用**。同时，它也不能证明所有读卡、标签、支付、公交或门禁场景都正常；具体 App、卡种和服务组合尚未逐项测试。

本项目公开证据尚未确定 OPPO 拒绝的准确原因。尤其无法单凭现象确认是固件地区、账户或服务资格、设备状态，还是其他开卡校验引起的。这些只是待诊断的问题，不能写成已确定原因。安装国内 NFC App、修改地区属性、重新加锁或运行 OTA updater，都不是本项目已经验证的修复办法。

记录问题时，应写清系统完整版本、App 名称及版本、卡片类别、失败步骤，以及完整提示或错误码。公开前隐藏账户标识、卡号和开卡令牌。可向对应 OPPO／App 支持渠道核实这次拒绝；保留目前可正常使用的系统，不要为了诊断加卡问题反复执行转版。XDA 与维护者链接见[来源说明](SOURCES.zh-CN.md)。

## 工具里的 `complete` 代表什么

CLI 最后检查欧版身份、预期项目号和槽位、解锁状态、Android 启动完成和初始化完成；前面的阶段检查安装证据、存储几何和读回结果。它不会执行完整的手机功能验收、安装未来 OTA，或尝试添加 NFC 卡片。因此，即使一个运行记录达到 `complete`，也不能据此认定上述两类服务限制已修复。

如果补充另一台真机的测试记录，应区分**手工转版**和**完整执行某个 CLI 提交版本**，记录机型、容量、起始及目标版本，并说明实际使用过哪些功能。不能根据项目名称较宽泛，就推断其他机型也受到支持。
