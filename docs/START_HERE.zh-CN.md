# 从这里开始

[English](START_HERE.md) | 简体中文 | [项目主页](../README.zh-CN.md)

本项目**纯属技术探索**。真实操作需要 Android 刷机知识、Linux 命令行经验，**以及 AI 的辅助**，共同核对确切文件、日志和下一步动作。这是本项目要求的操作前提，不代表有了 AI 就能安全刷机；操作者必须理解并核实每个破坏性步骤。实现与文档由 Codex 协助完成；前人贡献见[来源与致谢](SOURCES.zh-CN.md)。

历史手工转版仅在**一台 Find X9 Ultra / X9U、PMA110 512 GB** 上验证。新 CLI 尚未完成实机端到端转换。请先阅读[测试范围与 OTA/NFC 体验](COMPATIBILITY.zh-CN.md)。

| 你的情况 | 从哪里开始 |

| 全新、锁定的原厂 CN403，且与记录配置完全一致 | 读完本页，校验四个输入文件，然后逐阶段按 [CLI 第 1–7 节](CLI.zh-CN.md)操作。 |

| 刷到一半、已经解锁或修改过，或没有有效等待检查点的中断 | 保留当前现场，阅读[故障处理](TROUBLESHOOTING.zh-CN.md)。CLI 不能接管或修复任意已有状态。 |

## 操作手机前准备好

- Linux 电脑、Python **3.11+** 和 Google Platform Tools **37.0.1**；不需要 pip 依赖。不支持在 Windows/macOS 上执行。
- 四个确切文件：CN2EU ROM ZIP、GBL APK、OrangeFox IMG、OrangeFox ZIP。下载来源、大小和 SHA-256 见[文件校验表](CONVERSION.zh-CN.md)。
- 可靠的数据线，只连接一台目标手机，电量至少 50%；除下载文件占用外，电脑还要有足够空间保存指定分区备份并额外预留 1 GiB。程序在备份检查点计算所需容量。
- 单独备份并确认能够恢复个人数据及账户恢复所需信息。格式化和解锁都会清除数据；工具的分区备份不含个人数据，且生成时已经发生过初始修改。
- 开始前理解完整人工流程和停止条件；手机重启时，最好有另一块屏幕显示文档。

将**项目源码**下载或解压到本地，在包含 `change.py` 的目录打开终端。大体积输入文件放在其他目录。除明确标注“手机上操作”的步骤外，文档中的 shell 命令都在**电脑终端**执行。

```sh
python3 change.py --help
```

项目无需安装。[CLI 第 1 节](CLI.zh-CN.md)会设置工具目录、输入目录、运行目录、Android 序列号四个变量。把占位值换成自己的实际值；路径包含空格时保留引号。`prepare --out` 必须指向尚不存在的目录。

## 最常用的一条命令

`prepare` 创建运行目录后，随时只读查看当前检查点：

```sh
python3 change.py guide runs/convert --language zh-CN
python3 change.py guide runs/convert
```

将 `runs/convert` 换成**实际运行目录**。指引显示阶段、手机操作、需要使用哪类序列号，以及对应的 CLI 章节。它只读取本地日志，不核验手机实时状态，也不会推进流程；`status` 保留 JSON 输出供诊断。

| 命令或结果 | 该怎么理解 |
| --- | --- |
| `doctor` | 检查电脑上的 ADB/fastboot，不检查手机。 |
| `prepare` | 离线审计输入文件并建立新记录；大文件计算摘要需要时间。 |
| `guide` / `status` | 读取当前记录，不代表确认执行某个阶段。 |
| 不带 `--execute` 的 `run` / `resume` | 仅预览，不向手机发送命令。 |
| 执行命令退出码 **3** | 正常的人工检查点。阅读指引，完成手机操作，再使用对应章节的继续命令。 |
| 执行命令退出码 **2** 或 **130** | 阅读具体错误并保留现场。可能已经部分执行的动作不能直接重跑。 |
| 原进程结束后仍为 `running` / `executing`，或 `review_required` | 停止并人工核查。指引不再提供普通下一步操作。 |

`guide` / `status` 读取成功就返回 0，即使里面记录的是 `review_required`。**必须阅读实际阶段和状态。** 正常等待也不代表可以用循环自动执行 `resume`。

## 分清手机所处模式

| 名称 | 本流程中的含义 | 对下一步的影响 |
| --- | --- | --- |
| Android / ADB | 正常操作系统，已授权 USB 调试 | 起始与结束验证使用最初 Android 的 ADB 序列号。 |
| GBL / Bootloader fastboot | 上游 GBL 应用安装的引导访问方式 | 可能显示不同序列号，按 GBL 交接步骤处理；它不是 fastbootd。 |
| OrangeFox / Recovery | 独立恢复环境 | 普通 Recovery ADB 用于日志、备份和校验。只看到 Files 页面不代表安装成功。 |
| ADB Sideload | Recovery 接收 ZIP 的模式 | 只在对应等待阶段开启。传包完成和安装完成是两件事。 |
| `super` / GPT | Android 系统容器 / 分区表 | 转版会改变布局，不能套用其他容量机型的边界或临时猜命令。 |
| Format Data | Recovery 中指定的文件系统格式化操作 | 普通 wipe、别处的恢复出厂设置或删除文件都不能代替记录中的 OrangeFox 操作。 |

[截图与画面对照](SCREENSHOTS.zh-CN.md)可用于逐屏确认。照片只帮助识别画面，不能代替新日志及回读校验。

## 让 AI 协助核查，保留人的判断

向助手提供相关来源链接、非敏感的确切版本信息和脱敏错误片段。可以使用下面的请求：

> 阅读本项目 CLI、流程图和故障处理文档，把我的机型、容量、版本、内核、当前日志阶段与文档逐项对照。说明哪些检查已有证据、哪些还缺，以及下一步会改动什么。先做只读分析；发现证据不符或写入可能中断时停止并等待人工核查。不要编造强制继续、重试或重新加锁的方案。

不要上传完整运行目录、分区备份、序列号、IMEI、账户 token 或个人数据。AI 的回答需要人工核实，不能当成命令适用的证据。如果无法解释一次写入、格式化或重启的作用及前置条件，就不要执行。
