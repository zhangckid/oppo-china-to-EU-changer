# 故障处理与异常说明

[English](TROUBLESHOOTING.md) | 简体中文 | [项目主页](../README.zh-CN.md)

本文解释 CLI 结果和停止时如何保留证据，不提供通用修复步骤。检查失败可能意味着手机或写入状态已偏离经过审查的流程。

## 开始前

主机必须运行 Linux 和 Python 3.11 或更新版本。本版本不支持 Windows 或 macOS 主机。

- 仅使用与本仓库记录完全一致的 `PMA110`、512 GB、项目号 `25021`、CN403 版本及固定文件。本项目不支持所有 OPPO 设备，也不支持所有 PMA110/PMA120 配置。
- 另行备份个人数据。解锁和两次 Format Data 都会清除用户数据。工具的转版前备份不包含 `userdata`，不能当作个人数据备份。
- 准备固定版本 Android Platform Tools 37.0.1，目录中需有 `adb` 与 `fastboot`；执行前电量至少 50%。主机磁盘还需容纳所选全部分区备份及额外 1 GiB 空间。
- 首次命令前在手机授权 USB 调试。开始时只连接目标手机，并使用当前序列号。GBL fastboot 的序列号可能与 Android/Recovery ADB 不同。
- 每个阶段都先阅读 `status` 输出的操作说明。命令运行期间保持手机、USB 线和主机稳定。

`prepare` 只核验本地文件，不连接手机。它按固定大小和 SHA-256 检查每个输入，再检查转换 ZIP 和 sparse `super` 镜像。本地文件名不影响校验。不要修改固定摘要，也不要替换文件来绕过不匹配。`doctor` 只检查主机 Platform Tools，不读取手机状态。

## 退出码与运行状态

| 结果 | 含义 | 处理方式 |
| --- | --- | --- |
| 退出码 `0` | `prepare`、`doctor`、`status` 或成功完成的命令 | 阅读 JSON 结果；转版完成时确认 `stage` 和 `status` 均为 `complete`。 |
| 退出码 `3` | 正常检查点：执行阶段停在等待人工操作的状态 | 阅读屏幕说明和 `status`。仅执行要求的人工动作，然后使用确切的 `--ack-stage` 和正确序列号运行 `resume`。 |
| 退出码 `2` | 校验或执行遇错停止 | 保留运行目录和手机状态。查看 `STOP:` 信息和 `status`；若状态为 `review_required`，CLI 没有重置或绕过命令。需要人工针对设备复核。 |
| 退出码 `130` | 主机进程收到 Ctrl-C | 不要重跑操作。日志可能仍为 `executing`；下一次调用会将其标记为 `review_required`，不会重放操作。 |

写入、sideload、备份或读回期间意外断开或超时，可能留下部分操作。即使命令日志已有输出，也应保守地视为“完成状态未知”。主机命令成功返回本身不能证明 Recovery 安装器成功。

不带 `--execute` 的 `run` 仅预览，不发送设备命令。`resume` 只确认当前确切等待阶段，不是通用重试命令。GBL 交接时提供当前 GBL fastboot 序列号；`waiting_unlock` 阶段使用已绑定的 GBL 序列号；Recovery 和 Android 阶段使用最初绑定的 ADB 序列号。

## 停止条件及后续处理

| 错误信息或情况 | 含义 | 处理方式 |
| --- | --- | --- |
| 大小、SHA-256、ZIP 内容、sparse 镜像或固件清单不匹配 | 本地文件与经过审查的输入不一致。`prepare` 阶段不需要接触手机。 | 停止。从所列发布页/发布者处获取确切文件并重新核验。不要修改 `pins.json` 让不同文件通过。 |
| ADB 显示 `unauthorized`、无授权设备、检测到多个设备或序列号不同 | USB 传输不是本运行绑定的设备，或手机尚未授权这台电脑。 | 新运行开始前，在手机授权主机并仅连接目标设备。设备命令执行期间不要拔手机。若当前运行进入 `review_required`，先保留运行目录并人工核对手机状态，再决定后续操作。 |
| 缺少 Platform Tools 或版本不是 37.0.1 | 主机缺少经过审查的 ADB/fastboot 二进制。 | 安装官方版本后运行 `doctor --platform-tools PATH`。执行前的工具版本问题属于主机配置；运行中不要切换二进制。 |
| 模式错误、GBL fastboot 不符、进入 `fastbootd`、启动身份/GPT/分区容量/槽位/锁状态异常，或电量低于 50% | 设备状态偏离记录，或未准备好进入下一阶段。 | 停止。不要手动刷写、解锁或重启来强行制造预期状态。保留 `status` 和手机当前画面以供复核。 |
| Qualcomm `xbl_config` 元数据与经审查的 `(3, 0, 0)` 不同，或解析器报告元数据缺失/不唯一 | 无法从该固件镜像确认确切回滚元数据。这是镜像元数据解析，不会读取设备熔丝。 | 停止。不要替换或修补元数据，也不要修改 pins。针对新包寻求对应维护者复核。 |
| 等待阶段出现多个 USB 设备或序列号变化 | 检测到多个设备，或传输序列号变化。 | 新运行需只连接目标设备。进入 GBL 时按说明使用 GBL 序列号。设备绑定后，不要替换成其他 Android/Recovery 序列号。`review_required` 运行不能重新绑定。 |
| 备份空间不足、备份读取失败，或主机/设备 SHA-256 不一致 | 转版前快照不完整或数据不一致。 | 不要安装 OrangeFox ZIP 或 ROM。保留部分备份和日志；不要删除运行目录以便重试。先人工复核存储及设备状态。 |
| ROM sideload 前仍挂载 `/system`、`/vendor`、`/product`、`/system_ext` 或 `/odm` | 转版预检发现固件文件系统仍挂载。历史案例中触摸服务占用了 `/odm`。 | 停止。不要依据本文停止服务、强制/延迟卸载，也不要采用 ADB daemon 变通方法。记录阶段并针对确切 Recovery 版本寻求复核。CLI 不会自动修改系统服务。 |
| Recovery 界面重启、队列中仍有脚本，或安装/格式化期间 Recovery 日志被轮转 | 完成标记可能过期或缺失，CLI 无法证明实际结果。 | 不要再次运行安装器或格式化。保留 Recovery 画面与运行目录；旧日志中的 `Installation complete` 不能当作本次成功证据。 |
| OrangeFox 出现 ABL 提示时没有选音量下，或显示 `ABL=YES` | 保留 GBL 的引导链可能有风险。记录中的安装器流程要求 ABL **NO**。 | 不要选择 ABL YES。若已经选中，立即停止流程，不要重启或尝试其他刷写，并寻求针对本次状态的复核。 |
| sideload 主机端显示完成，但日志没有新的 `Installation complete`、报错或未确认保留 ABL | 主机传输结果不能证明设备端安装成功。 | 不要 Format Data 或启动 Android。将 Recovery 保持在当前状态并保存日志；不要在写入不确定时重复 sideload。 |
| ADB/fastboot 命令超时、命令期间 USB 断开、分区备份/读回不完整，或操作可能已开始但没有核验结果 | 即使主机进程超时或结束，操作仍可能部分完成。 | 不要重试、重连后重放、重启、切槽或删除部分备份证据。保留手机当前模式和运行目录以便人工复核。 |
| 全新 Recovery 检查发现 GPT、GBL、OrangeFox、固件或 sparse `super` 区域摘要不匹配 | 受保护组件或预期写入不符合确切摘要/布局。 | 停止。不要启动 Android、回锁、切换槽位或猜测镜像刷入。保存所有证据并寻求针对设备的恢复建议。 |
| Format Data 失败、日志证据过期，或全新 Recovery 启动后 `/data` 未以 F2FS 挂载 | 所需人工格式化尚未验证。检查需要 `/dev/block/sda15` 和 `/dev/block/sda10` 各自成功的 `mkfs_f2fs` 记录，之后全新 Recovery 中 `/data` 已挂载。 | 不要启动 Android，也不要仅凭旧提示重复格式化。保留当前 Recovery 与日志以便复核。 |
| Android 未达到预期欧版身份/初始化界面，或设备进入启动循环 | 最终启动验证失败或无法执行。 | 不要回锁、重复转版或刷入未经审查文件。Bootloader 保持解锁，记录当前画面与上次运行阶段，并寻求熟悉该设备的恢复帮助。 |

## 证据与隐私

使用 `python3 change.py status RUN_DIR` 查看日志状态。私下保存整个运行目录：`state.json`、`manifest.json`、`commands.jsonl`、所有 `*.log` 和备份记录有助于确定发生了什么。日志和命令文件可能包含序列号、主机路径、分区数据和其他隐私。公开前请检查并脱敏；不要公开固件/备份或完整运行目录。

寻求帮助时，请给出确切机型/容量、源版本、项目号/内核、文件名及摘要、手机当前画面/模式、最后成功阶段、完整报错文本，以及写入是否可能已开始。不要公开序列号、账户令牌、个人备份或未脱敏日志。如果运行状态为 `review_required`，工具刻意没有“强行继续”命令。

XDA 和维护者链接见[来源与溯源](SOURCES.zh-CN.md)。社区讨论可用于寻找熟悉该设备的人员，但不要复制其他机型或版本的流程。
