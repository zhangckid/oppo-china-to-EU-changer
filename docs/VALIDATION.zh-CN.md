# 验证记录

[English](VALIDATION.md) | 简体中文 | [项目主页](../README.zh-CN.md)

本文将历史手机转版记录与新 CLI 的验证分开。它们是不同的证据。

## 历史实机证据

一台 512 GB 的 OPPO Find X9 Ultra `PMA110`，项目号 `25021`，源版本 `PMA110_16.0.9.403(CN01)`，内核 `6.12.58-android16-6-g7704a1ae279b-ab15213644-4k`，使用指定 CN2EU 包手动转为 `CPH2841_16.0.9.403(EX01)`。首次安装在 `super` 写入约 50% 时被人工中断；此前 GPT 已扩展、100 个固件目标已写入，而 `super` 只写入一部分。操作者没有启动手机。审计设备、GPT、进程、日志和保留的引导链分区后，才重新运行完整 ZIP；手机随后进入 Android 初始化界面。这是基于该确切案例的人工判断，不是自动恢复依据。

记录的核验包括安装器成功完成、GPT/布局与 `super` 几何检查、确认 GBL/ABL、EFISP 和两个 OrangeFox Recovery 槽位仍保留，以及 Format Data 前启动全新 Recovery 会话。设备随后成功进入欧版 Android 初始化界面。这些证据只适用于记录中的设备和确切输入，不能证明所有功能均正常、OPPO 官方支持此转版，或未来版本兼容。

## 新 CLI 状态

新工具**尚未用于真实手机刷写**。确切固定的 ROM、GBL APK、OrangeFox IMG 和 ZIP 均已离线核验；13,346,334,129 字节的 ROM 有 64 个 ZIP 条目和 53 个镜像文件，其中 50 张为选定的固件镜像。sparse `super` 展开后为 20,451,426,304 字节，共有 309 个块：290 个已定义 RAW/FILL 区域具有摘要，另有 19 个 DONT_CARE 区域的内容未定义。检查器不会从手机读取这 19 个区域，也不声称它们匹配某种确定字节模式。离线准备过程未访问设备，也未发送 USB 命令。

提供 `--execute` 时，CLI 可以向真实设备发送 ADB/fastboot 命令；但设备行为的验证目前仅来自基于模拟设备的单元测试。测试覆盖解析器、阶段检查、模拟传输、故障、中断处理和源码导出，不能证明实机响应、Recovery 界面步骤或镜像写入正确。若考虑在真实设备上使用，必须将其视为实验性工具，并认识到运行中断可能令手机状态不确定。

本仓库不包含真实手机序列号、完整私有刷机日志、固件镜像、备份或用户数据。源码导出清单应只包含源码、公开文档和合成测试数据。

## 更改此状态所需证据

在宣称支持实机前，维护者需要审查最终代码，并为确切机型/版本/内核组合单独记录受控实机验证。证据应包括已核验输入摘要、每个阶段的状态检查、私下留存的完整未删节日志、受保护引导链和目标分区的独立读回、新 Recovery 与 Format Data 检查，以及 Android 成功启动核验。公开报告需隐去序列号、账户信息、令牌和其他隐私。测试一个配置仍不代表广泛支持 OPPO 设备。
